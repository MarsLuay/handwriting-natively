# Decisions

- Keep undocumented Obsidian PDF integration behind the adapter boundary in `src/integration/`; the generic annotation engine and tests should depend only on `AnnotationSurface`, while PDF.js/private host capabilities remain optional extensions.
- Treat sidecar JSON as the canonical editable annotation data, with page-space coordinates; use separate recovery data for crash recovery and separate files for exports.
- Pencil-first / device-aware input: stylus (`pointerType === "pen"`) annotates with the active tool immediately; finger touch stays native PDF pan/pinch (never inks); desktop primary mouse starts annotation only when the gesture begins over a PDF page, while empty viewer space retains the configured `mouseInputMode` (`pan` | `annotate` | `native`) behavior. Do not globally apply `touch-action: none`.
- Default autosave on. Completed annotation commands schedule persistence after the documented 750 ms debounce; closing a PDF flushes, and manual-save mode requires an explicit save/discard/cancel choice when dirty.
- Keep operation local to the vault/device: no telemetry, hosted service, CDN, remote AI, OCR, or handwriting recognition. Issue #141's post-UI Pencil probe is diagnostic-only local vault logging: it is debug-gated, time/event bounded, records metadata and point counts rather than annotation contents, and never changes route ownership or touch-native policy.
- Share one toolbar, tool state, history, storage, autosave, and recovery path across direct/embedded PDF views and one-page image surfaces. PDF export and page mutation remain optional PDF-surface actions; image export is a separate flattened copy that preserves the source PNG/JPEG format and leaves the image plus sidecar unchanged.
- Import page (More menu): copy selected native pages via `PDFDocument.copyPages` into the open PDF after the current page in one source-PDF write, then shift later sidecar page indices by the imported count. Destination and source bytes load independently so self-import cannot corrupt the open document; picker cancel and load failures leave PDF+sidecar unchanged.
- Scan document (More menu, mobile/tablet): request rear-camera capture at action time, review crop/perspective/rotate/retake, then insert one or more image-backed pages after the current page in one atomic PDF+sidecar+recovery write (`writePdfAndAnnotationStoresAtomic` / `insertScannedPages`). Cancel or permission deny leaves the open PDF unchanged; desktop omits the action.
- Page structure actions are an explicit source-PDF mutation boundary: Add page, Delete page, Import page, and Scan document rewrite the open PDF only through `writePdfAndAnnotationStoresAtomic`, remap sidecar/recovery page numbers, and compensate the PDF/store writes on failure. Ordinary annotation edits and Export PDF remain non-destructive. Add Page additionally captures bounded view/layout evidence, defers PDF.js scale-mode restoration until the expected replacement page set is observable (or restores it before a new session is created after detach), and diagnoses stale generations rather than compositing them.
- pdf-lib page mutation preserves in-place metadata, outlines, AcroForm, and page annotations on the original page object. `copyPages` keeps page size, rotation, content, and page annotations, and drops destination-side title, outlines, and catalog AcroForm. PDFs with signature dictionaries or encryption are refused before save. Ink follows remapped page numbers; stable page UUIDs stay with #133. Reorder and duplicate are not part of this mutation set.
- Post-UI probe diagnostics classify only observed `pointerType === "pen"` contacts as Pencil outcomes. Touch-only or empty expiry windows remain informational with `penObserved: false`, observed pointer types, contact count, and transition context.
- UI-surface lifecycle diagnostics canonicalize nested Obsidian shell nodes to the outer same-kind shell, while menus/popovers remain separate surfaces. Lifecycle IDs come from the canonical shell and nested-node IDs/counts remain bounded diagnostic context.
- Every debug-traced real Pencil contact exposes its stable handoff correlation as `penContactId` across document, routing, fallback, and terminal diagnostics; existing `correlationId` remains for compatibility.
- Stroke identity diagnostics keep `strokeId` separate from persisted ink data and correlate it with the optional `penContactId` at route start, creation, model insertion, pointerup/commit, and bounded model removal events. Model-removal reasons are explicit; the lifecycle listener is diagnostic-only and capped to recent contact mappings, with absent contact identity represented as `null`.
- Render lifecycle diagnostics keep committed stroke identity separate from pixels: bounded per-stroke state records first render, paint acknowledgement, canvas-generation rebuilds, repaint inclusion/omission, zoom-settle checks, and delayed model-present regressions without persistence or pixel verification. Generation counters are debug-gated through the existing local `SessionLogger` and do not alter rendering behavior.
- Persistence lifecycle diagnostics correlate the same `strokeId` and optional `penContactId` through successful recovery/sidecar serialization, final sidecar-and-recovery persistence, and reload restoration. Snapshot omissions are explicit bounded warnings with reasons; the existing atomic write ordering and schema remain unchanged.
- Pixel evidence is debug-only and bounded to one capped affected region per stroke and paint generation, plus one delayed committed-canvas sample. It reports pre/post alpha presence and canvas/paint generations without coordinates or image data, and always reports `pixelVisibilityVerified: false` with a reason when sampling is unavailable or cannot prove visibility.
- Supported-content activation uses a durable `enabledSurfaces` settings object (`pdf`, `image`, and `markdown`) so missing legacy values default on. Disabling PDFs or static PNG/JPEG image annotation persists annotations, tears down existing sessions, skips future attachment, and logs one bounded state-change diagnostic; re-enabling schedules the normal scan. Markdown remains reserved for embedded PDF chrome.
- Large-document rendering uses a measured working-set policy rather than a universal page/byte target: visible validated pages are protected, offscreen raster/preload entries are evicted by bounded LRU accounting, wet ink is synchronous, finalized/HQ work is deferred and generation-cancelled, and mobile/device budgets remain explicitly unqualified until physical runtime traces are captured. Render cache keys are document, page, scale, rotation, content revision, and renderer generation. Memory pressure uses that same offscreen-raster eviction and does not read system RAM.
- Mouse drag bindings are explicit settings: primary-button drawing is enabled by default, secondary-button erasing is disabled by default, and disabled bindings fall through to the host PDF viewer's normal pan/context-menu behavior. A malformed sidecar or recovery file is removed after quarantine when no validated backup or last-good snapshot can restore it; the empty store is then authoritative.
