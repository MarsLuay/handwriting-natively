# Quirks

- Laser pointer trails fade and are never saved. Pen, pencil, highlighter, and typed text are sidecar-backed; typed text is searchable through the viewer-only bridge, while freehand ink is not searchable.
- The adapter checks known viewer/page selectors and falls back to DOM page bounds. A missing viewer root or page is a hard compatibility error; a missing embedded host toolbar is a warning because the shared toolbar can mount beside the viewer.
- Direct PDFs, PNG/JPEG images, and Markdown Reading/editing views use the same draggable floating `AnnotationToolbar`; More rotates its persisted horizontal/vertical orientation. Markdown editing mounts outside CodeMirror's contenteditable subtree and follows the full scrollable note; native typing, selection, keyboard input, and scrolling remain available unless an annotation gesture is claimed. Direct PDF mounting does not depend on Obsidian's private `PDFToolbar` constructor or a host `.pdf-toolbar` element.
- Markdown keeps one full-note canvas. Its edge allowance is 16,384 pixels on desktop and 8,192 on mobile while retaining each platform's existing pixel-area budget, so note height alone does not downscale strokes as early as on paginated surfaces.
- Markdown's note-wide ink overlay stays below native `![[PDF]]` embed hosts so Obsidian's embedded PDF renderer and toolbar remain visible and usable.
- Pointer samples update in-memory strokes. Completed commands—not every pointer sample—mark the document dirty and schedule persistence. One queue entry serializes writes per document; newer snapshots follow an in-flight write.
- Pointer capture cleanup handles `lostpointercapture` for mouse ink as well as pen ink. The capability probe reports pen remapping after hover, off-host wheel panning, and that real `TouchEvent`s are still required for companion/multi-touch behavior.
- MacBook Force Touch pressure is unavailable through Obsidian/Electron; stylus pressure works only when exposed by the host OS.
- Shape recognition is enabled by default in each drawing tool's Advanced settings and uses a 0.5-second hold for confident supported shapes; ambiguous writing remains ink.
- Pen occlusion: only active Obsidian shells (open/pinned drawers, modals, menus) block geometric pen recovery. Closed drawers and bare layout nodes such as `.vertical-tab-content` / `.setting-item` that linger in `elementsFromPoint()` after Settings close do not count as `ui-occluded`. Genuine open UI still skips with `ui-occluded` and emits a deduped `pen-occlusion-anomaly` record.
- Mobile plugin reloads can occur after Obsidian has already published `layout-ready` without another PDF lifecycle event; `NativePdfInkPlugin` therefore queues an immediate attach scan on plugin load. Failed attachment before session registration must destroy the adapter so the next retry does not inherit stale listeners or surfaces.
- Runtime frame cadence uses bounded active and sparse idle rAF samples. A stable active ~33 ms cadence remains a possible every-other-frame 60 Hz miss and keeps the conservative fallback until idle evidence confirms a genuine lower-refresh runtime.
- Stroke `frame-gap` telemetry is elapsed time between presentation callbacks, not synchronous plugin work; callback/canvas active work and scheduling latency remain separate correlated spans.
- Live ink coalesces to one visible-surface rAF, with a single frame-budget-plus-slack timer fallback only when a visible browser misses that next callback; terminal input cancels stale scheduled work and commits synchronously.
- Zoom frame attribution reports only observed causes; unsupported Long Task observation is retained as a bounded `limitations` field and never presented as the cause of an unexplained gap.
