# Architecture

- `src/main.ts` is the plugin entrypoint. It composes direct and embedded PDF adapters, one-page image adapters, per-view `ViewerInkSession` instances, settings, storage, recovery, PDF services, and vault debug logging.
- `src/runtime/AnnotationSurface.ts` defines the minimal generic page-surface contract: page identity/geometry, view and scroll lifecycle, overlay/UI mounting, and teardown. Its optional `surfaceType` distinguishes PDF, image, and Markdown content. `src/integration/ObsidianPdfAdapter.ts` keeps PDF.js/private-Obsidian capabilities as an optional extension; `ImageViewAdapter` supplies a one-page top-left-coordinate surface without converting the image to PDF; `MarkdownViewAdapter` is a non-registered Reading-view scaffold for future use.
- `src/integration/PluginPdfView.ts` and `PdfJsViewAdapter.ts` implement the plugin-owned PDF path for issue #460. PDF.js remains the parser/raster/text/annotation engine, but the plugin owns the public `ItemView`, page shells, scroll/zoom state, lifecycle generations, and same-DOM ink overlays. `PdfJsRuntime.ts` and the small packaged-runtime loaders resolve only version-pinned local assets staged under `pdfjs/`; native Obsidian leaves remain a reversible fail-closed fallback. Its owned toolbar provides navigation, zoom presets, rotation, outline/thumbnails, search, hand-pan, presentation, print, and download without adopting PDFViewerApplication's singleton.

- `src/input/`, `src/ink/`, `src/tools/`, `src/history/`, and `src/ui/` implement shared pointer policy, page-local ink, tool behavior, edit history, and toolbar/dropdown UI. PDF and image surfaces consume the same session/engine behavior. Pen, Pencil, and Highlighter are permanent drawing tools with independent persisted settings; legacy preset data is migrated once and then discarded.
- `src/storage/` owns document identity, versioned sidecars, autosave/manual save coordination, recovery, and vault writes. Sidecar JSON is the documented canonical editable annotation store; recovery is separate. Existing-primary replacement preserves a validated `.last-good` sidecar before overwrite, while external changes remain conflict-protected. Fire-and-forget unload writes serialize per adapter/path, stage and verify an `.emergency.tmp` snapshot, reject stale overwrites, and leave the newest validated candidate recoverable when canonical replacement is interrupted.
- `src/pdf/` creates blank PDFs, inserts/deletes pages, maps coordinates, and exports annotated copies. Explicit page insertion/deletion/import/scan actions rewrite the open source PDF through `writePdfAndAnnotationStoresAtomic`; export writes a separate copy.
- Each attached viewer owns a disposable session. Close, note switching, and unload flush persistence, release captures/listeners, remove overlays, restore integration state, and release viewer references. Page-bound `PointerRouter` instances also cancel plugin-owned routes and clear pen/touch ownership on blur, pagehide, and hidden visibility before native navigation can be resumed.
- `esbuild.config.mjs` bundles `src/main.ts` to `main.js`, externalizing `obsidian`, `electron`, and Node built-ins; production mode minifies and copies the plugin artifacts to the vault plugin directory.
- `SessionLogger` emits versioned, local-only bounded diagnostics for effective draw-state transitions, zoom bursts, strokes, pans, rendering, persistence, and the post-UI input probe. `PhysicalContactCollector` owns one document-capture listener set, shares it across page/session owners, deduplicates raw browser events, and routes one authoritative `PhysicalContactTracker` per document; the tracker retains stable physical IDs, separate raw evidence, bounded movement summaries, and explicit classification transitions. `PostUiInputProbe` links that ID through document hit recovery, page-router delivery, route/claim/pan stages, terminal ink, and sidecar persistence, then expires with a missing-event summary and emits one bounded terminal anomaly trace for failed or conflicting contacts. `PerformanceMetrics` retains only bounded timing samples for summaries; no network telemetry or per-frame log stream is used. Large-document policy is documented in `docs/large-document-performance-strategy.md`: visible validated pages remain mounted, offscreen state stays logical, raster/vector caches are keyed and bounded, expensive work is staged/cancelled by generation, and per-device budgets remain unqualified until manual runtime traces exist. `tests/fixtures/largeDocumentWorkloads.ts` is the canonical deterministic workload/trace schema; its sanitizer bounds timing samples and excludes annotation content from copied evidence.
