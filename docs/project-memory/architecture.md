# Architecture

- `src/main.ts` is the plugin entrypoint. It composes direct and embedded PDF adapters, one-page image adapters, per-view `ViewerInkSession` instances, settings, storage, recovery, PDF services, and vault debug logging.
- `src/runtime/AnnotationSurface.ts` defines the minimal generic page-surface contract: page identity/geometry, view and scroll lifecycle, semantic page/zoom signals, overlay/UI mounting, teardown, and bounded page evidence gates for safe input/persistence. `src/integration/ObsidianPdfAdapter.ts` keeps PDF.js/private-Obsidian capabilities as an optional extension; `ImageViewAdapter` supplies a one-page top-left-coordinate surface for static PNG and JPEG/JPG files without converting the image to PDF, plus an optional source-image export capability. Unsupported image extensions stay outside session attachment, and the durable image surface switch detaches existing image sessions. PDF adapters prefer validated viewer events and use bounded DOM fallback without exposing raw EventBus objects to the session.
- `src/integration/` owns undocumented Obsidian PDF objects, DOM selectors, viewer discovery, compatibility probes, page location, and cleanup. Each PDF adapter emits one bounded schema-versioned compatibility profile per viewer instance; optional private capabilities degrade independently while missing identity/geometry evidence is unsafe. Viewer generations are per adapter, and `PdfPageLocator` separates logical page numbers from ephemeral DOM-shell mount generations. Duplicate-shell discovery reports candidate count, geometry/identity confidence, and an explicit unsafe result when no live shell can be proven. During a PDF replacement, compatibility discovery prefers the private viewer hint or newest rendered viewer/toolbar shell instead of the first connected selector match, preventing shared tools from mounting into a stale shell. Sidebar/toolbar rail tracking is optional layout capability; missing signals degrade layout only and zoom suppression never remounts pages. `src/focus-view/` handles embedded annotate chrome and opening a PDF leaf.
- `src/input/`, `src/ink/`, `src/tools/`, `src/history/`, and `src/ui/` implement shared pointer policy, page-local ink, tool behavior, edit history, and toolbar/dropdown UI. PDF and image surfaces consume the same session/engine behavior. Drawing presets live in settings, are capped during migration, and apply tool plus style as one action.
- Add Page controls use host-scoped ownership for both the page-end button and thumbnail-sidebar action surface. A new viewer/session generation disposes the previous owner, reconciles stale controls to one connected instance, and emits bounded duplicate/mount lifecycle diagnostics. `ViewerInkSession` also reconciles the shared handwriting toolbar after page/viewer lifecycle changes and emits bounded missing-UI evidence when the expected current generation is still absent after settle.
- `src/storage/` owns document identity, versioned sidecars, autosave/manual save coordination, recovery, and vault writes. Runtime persistence skips snapshots whose live page evidence is unsafe, preserving the last validated sidecar. Sidecar JSON is the documented canonical editable annotation store; recovery is separate. Existing-primary replacement preserves a validated `.last-good` sidecar before overwrite, while external changes remain conflict-protected. Validated sidecar and recovery snapshots are also backed up in the configurable vault-relative annotation-backup folder (beside the debug log by default), and malformed stores are quarantined then automatically restored from a validated backup when recovery is enabled by default.
- `src/pdf/` creates blank PDFs, inserts/deletes pages, maps coordinates, and exports annotated copies. `src/image/ImageRasterExportService.ts` bounds flattened PNG/JPEG output dimensions, preserves PNG alpha, composites an opaque JPEG background, and encodes a separate copy from the live source image. Both exports receive current page-space annotations from `ViewerInkSession`; the shared page mapper supplies image orientation/alignment rather than a parallel coordinate model. Explicit page insertion/deletion/import/scan actions rewrite the open source PDF through `writePdfAndAnnotationStoresAtomic`; export writes a separate copy.
- Page mutations can recreate the native PDF viewer. Add Page captures bounded view/DOM geometry evidence before the source-PDF rewrite, restores PDF.js scale mode and scroll state only after the expected replacement page set is observable (or before a new session is created after detach), and carries a short-lived restore record through session detach/re-attach so stale page/surface overlap is observable without retaining unbounded DOM state.
- Each attached viewer owns a disposable session. `NativePdfInkPlugin` is the session-registry owner: register/remove/destroy and replacement-attach lifecycle events include bounded viewer/UI/input-collector ownership, while copy-time diagnostics also emit a plugin-level snapshot so a detached session cannot make an active PDF silently disappear from the report. A settled visible PDF with zero registered sessions deterministically clears only that document's attach backoff, waits for stale session destruction, and re-attaches one authoritative session; failed recovery remains bounded by the normal retry policy and records an explicit blocker. Close, note switching, and unload flush persistence, release captures/listeners, remove overlays, restore integration state, and release viewer references.
- `esbuild.config.mjs` bundles `src/main.ts` to `main.js`, externalizing `obsidian`, `electron`, and Node built-ins; production mode minifies and copies the plugin artifacts to the vault plugin directory.
- `SessionLogger` emits versioned, local-only bounded diagnostics for effective draw-state transitions, zoom bursts, strokes, pans, rendering, persistence, and the post-UI input probe. `PhysicalContactTracker` observes document-level PointerEvent/TouchEvent lifecycles with stable physical IDs, separate raw evidence, bounded movement summaries, and explicit classification transitions. `PostUiInputProbe` links that ID through document hit recovery, page-router delivery, route/claim/pan stages, terminal ink, and sidecar persistence, then expires with a missing-event summary and emits one bounded terminal anomaly trace for failed or conflicting contacts. `PerformanceMetrics` retains only bounded timing samples for summaries; no network telemetry or per-frame log stream is used. Large-document policy is documented in `docs/large-document-performance-strategy.md`: visible validated pages remain mounted, offscreen state stays logical, raster/vector caches are keyed and bounded, expensive work is staged/cancelled by generation, and per-device budgets remain unqualified until manual runtime traces exist. `tests/fixtures/largeDocumentWorkloads.ts` is the canonical deterministic workload/trace schema; its sanitizer bounds timing samples and excludes annotation content from copied evidence.
