# Architecture

- `src/main.ts` is the plugin entrypoint. It composes direct and embedded PDF adapters, one-page image adapters, per-view `ViewerInkSession` instances, settings, storage, recovery, PDF services, and vault debug logging.
- `src/runtime/AnnotationSurface.ts` defines the minimal generic page-surface contract: page identity/geometry, view and scroll lifecycle, overlay/UI mounting, and teardown. Its optional `surfaceType` distinguishes PDF, image, and Markdown content. `src/integration/ObsidianPdfAdapter.ts` keeps PDF.js/private-Obsidian capabilities as an optional extension; `ImageViewAdapter` supplies a one-page top-left-coordinate surface without converting the image to PDF; `MarkdownViewAdapter` is a non-registered Reading-view scaffold for future use.
- Direct PDF files use Obsidian's native PDF view and `.pdf-toolbar` by default; the shared annotation session mounts the plugin's ink tools without replacing native navigation controls. Persisted leaves from the former plugin-owned viewer are migrated back to native on workspace restore. `PluginPdfView.ts` and `PdfJsViewAdapter.ts` remain registered only so those legacy leaves can be restored and migrated; the owned viewer is no longer selected for new PDFs.

- `ViewerInkSession` owns the cloned canonical `ViewerState` used by commands, persistence, and restoration. `HandwritingViewport` applies the live visual transform and reports viewport changes into that snapshot; PDF adapters own their rendered/platform state and report changes through the session callbacks. Add Page captures and reapplies the same canonical snapshot after replacement pages are ready. The native pre-session Add Page recovery path restores the adapter before creating the session. `PluginPdfView` state handling remains only for migration of legacy saved leaves.

- `src/input/`, `src/ink/`, `src/tools/`, `src/history/`, and `src/ui/` implement shared pointer policy, page-local ink, tool behavior, edit history, and toolbar/dropdown UI. Each viewer session shares one `GestureNavigationController` across its page routers for eligible one-finger pan, two-finger pan/pinch, hand-tool movement, modifier-wheel zoom, stylus exclusion, and navigation cleanup. `PointerRouter` delegates movement to it. PDF and image surfaces consume the same session/engine behavior. Pen, Pencil, and Highlighter are permanent drawing tools with independent persisted settings; legacy preset data is migrated once and then discarded.
- The native Obsidian PDF toolbar remains the default navigation surface. Legacy plugin-owned viewer navigation, zoom, rotation, search-open, and Hand controls still bind through the PDF adapter extension to the session's `ViewerCommandController` while an old saved leaf is being migrated; adapter fallback zoom buttons use the shared `VIEWER_ZOOM_STEP`.
- `src/storage/` owns document identity, versioned sidecars, autosave/manual save coordination, recovery, and vault writes. Sidecar JSON is the documented canonical editable annotation store; recovery is separate. Existing-primary replacement preserves a validated `.last-good` sidecar before overwrite, while external changes remain conflict-protected. Fire-and-forget unload writes serialize per adapter/path, stage and verify an `.emergency.tmp` snapshot, reject stale overwrites, and leave the newest validated candidate recoverable when canonical replacement is interrupted.
- `src/pdf/` creates blank PDFs, inserts/deletes pages, maps coordinates, and exports annotated copies. Explicit page insertion/deletion/import/scan actions rewrite the open source PDF through `writePdfAndAnnotationStoresAtomic`; export writes a separate copy.
- Each attached viewer owns a disposable session. Close, note switching, and unload flush persistence, release captures/listeners, remove overlays, restore integration state, and release viewer references. Page-bound `PointerRouter` instances cancel plugin-owned routes; the shared navigation controller releases captures and touch state, while lost pointer capture alone preserves pen exclusion until a real terminal or stale-pen recovery. If a requested sidebar rail is unavailable, the toolbar floats with a drag handle and returns to the rail when it appears; teardown removes its observer and drag listeners.
- `esbuild.config.mjs` bundles `src/main.ts` and the pinned PDF/runtime dependencies to `main.js`, externalizing only `obsidian`, `electron`, and Node built-ins; production mode minifies and copies the three BRAT plugin artifacts to the vault plugin directory.
- `SessionLogger` emits versioned, local-only bounded diagnostics for effective draw-state transitions, zoom bursts, strokes, pans, rendering, persistence, and the post-UI input probe. `PhysicalContactCollector` owns one document-capture listener set, shares it across page/session owners, deduplicates raw browser events, and routes one authoritative `PhysicalContactTracker` per document; the tracker retains stable physical IDs, separate raw evidence, bounded movement summaries, and explicit classification transitions. `PostUiInputProbe` links that ID through document hit recovery, page-router delivery, route/claim/pan stages, terminal ink, and sidecar persistence, then expires with a missing-event summary and emits one bounded terminal anomaly trace for failed or conflicting contacts. `PerformanceMetrics` retains only bounded timing samples for summaries; no network telemetry or per-frame log stream is used. Large-document policy is documented in `docs/large-document-performance-strategy.md`: visible validated pages remain mounted, offscreen state stays logical, raster/vector caches are keyed and bounded, expensive work is staged/cancelled by generation, and per-device budgets remain unqualified until manual runtime traces exist. `tests/fixtures/largeDocumentWorkloads.ts` is the canonical deterministic workload/trace schema; its sanitizer bounds timing samples and excludes annotation content from copied evidence.
- `IpadPointerTouchTrace` is a passive, debug-gated iPad observer. Its bounded trace retains ordered pointer boundary/contact events with browser and capture timestamps plus pressure, contact geometry, tilt, and twist; first/last hover sensor samples preserve hover-to-contact evidence without logging every move. Physical release rows remain unqualified until copied traces come from the named iPadOS/Obsidian builds.
